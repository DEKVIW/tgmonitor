# 学习资料链接去重外键故障修复记录

## 1. 故障概述

2026-11-22，后台执行学习资料相关的链接去重时，批量删除重复消息失败。接口返回 PostgreSQL 外键错误：

```text
psycopg2.errors.ForeignKeyViolation:
update or delete on table "messages" violates foreign key constraint
"learning_resource_items_first_source_message_id_fkey"
on table "learning_resource_items"
DETAIL: Key (id)=(580016) is still referenced from table "learning_resource_items".
```

失败 SQL 是批量删除 `messages`。本次删除集合中包含消息 ID `580016`，该消息仍被学习资料记录作为首条来源消息引用。

## 2. VPS 核查结果

受影响的示例数据如下：

| 数据 | 值 |
| --- | --- |
| 消息 ID | `580016` |
| 消息标题 | `26-27学年西安市期中考试真题（7-9年级）（全科）` |
| 学习资源 ID | `1930` |
| 首条来源消息 | `580016` |
| 最新来源消息 | `580016` |
| 转存任务 ID | `526` |
| 转存任务来源消息 | `580016` |

VPS 当前还有大量历史引用：约 `384` 个学习资源、`512` 个学习资料转存任务和 `827` 条处理日志保存了消息来源关系。因此这是删除流程与学习资料模块之间的系统性兼容问题，不是某一条消息的异常数据。

## 3. 实际失败流程

1. 去重逻辑先识别重复消息，并把待删除消息 ID 放入批量集合。
2. `app/services/dedup_runtime_service.py` 调用统一的消息资源清理函数。
3. 清理函数删除消息链接引用、点击记录，并清理可能孤立的链接目标。
4. 清理函数没有解除学习资料表中的 `source_message_id` 引用。
5. PostgreSQL 检查到 `messages.id=580016` 仍被引用，拒绝删除消息。
6. 去重事务整体回滚，所以本轮没有删除部分消息，也没有写入成功的去重统计。

相关代码位置：

- 去重删除入口：`app/services/dedup_runtime_service.py`
- 统一消息资源清理：`app/services/resource_ops/catalog.py`
- 学习资料模型和启动兼容迁移：`app/models/models.py`

## 4. 根本原因

学习资料模型中的以下三个外键虽然字段允许为空，但没有配置删除行为：

```text
learning_resource_items.first_source_message_id
learning_resource_items.latest_source_message_id
learning_resource_transfer_jobs.source_message_id
```

字段允许 `NULL` 不代表删除父记录时数据库会自动置空。当前约束默认使用 `NO ACTION`，所以父消息删除前必须先解除引用，否则会触发 `ForeignKeyViolation`。

以下引用目前已经配置为 `ON DELETE SET NULL`，不属于本次错误来源：

- `learning_resource_process_logs.source_message_id`

消息链接引用和点击记录由统一清理函数在删除消息前显式清理，因此本次错误也不是它们导致的。

## 5. 修复内容

### 5.1 模型约束修复

将三个学习资料来源消息外键统一改为：

```text
ON DELETE SET NULL
```

消息删除后，学习资料、转存任务和处理日志仍然保留，仅将已经不存在的来源消息字段置空。

### 5.2 运行时删除保护

在统一消息删除清理函数中，执行消息删除前主动置空：

- 学习资源的首条来源消息
- 学习资源的最新来源消息
- 转存任务的来源消息

这样即使 VPS 还没有完成数据库约束迁移，当前所有经过统一清理函数的删除入口也不会再次被旧约束阻塞。

### 5.3 VPS 兼容迁移

启动时检查三个外键约束：

- 旧约束不是 `SET NULL` 时替换为正确约束
- 正确约束已存在时不重复创建
- 新数据库由模型定义直接创建正确约束

迁移不删除任何学习资源、转存任务、处理日志或网盘文件。

### 5.4 来源链接目标保护

消息删除后，如果来源链接目标仍被学习资料链接或学习资料转存任务使用，则不再把该链接目标误判为孤立对象并删除，避免修复消息外键后继续触发链接目标外键错误。

## 6. 数据安全边界

本次修复只解除已删除消息的历史来源引用：

- 不删除学习资料记录
- 不删除学习资料转存任务
- 不删除处理日志
- 不删除网盘文件或分享
- 不改变重复消息的保留判定
- 不改变链接去重匹配规则

此前失败的去重事务已经回滚，不应手动删除消息或手动修改业务数据。部署修复后，重新执行去重即可重新计算并写入统计。

## 7. 验证方案

部署后依次验证：

1. 检查三个外键的删除动作均为 `SET NULL`。
2. 查询消息来源引用数量，确认历史数据仍存在。
3. 重新执行链接去重。
4. 确认本轮返回成功，并写入 `dedup_stats`。
5. 确认重复消息删除数量正常，学习资料记录和转存任务仍存在。
6. 检查 `tg-api`、`tg-worker`、`tg-monitor` 均为 active。
7. 检查服务日志没有新的 `ForeignKeyViolation`。

## 8. 回滚边界

如果部署后出现异常，应先停止重复执行去重任务，保留当前数据库状态并查看服务日志。代码回滚不会自动回滚已经成功的消息去重结果，因此回滚前应先保存去重统计和删除消息 ID。数据库约束回滚只允许在确认原因后进行，不能使用 `git reset --hard` 或直接删除业务表。

# 转存中心使用说明

> 适用范围
>
> - 对应当前后台 `资源运营 -> 转存中心`
> - 当前真实页签只有 4 个：`网盘账号`、`批量转存`、`追更同步`、`运营发布`
> - 本文只说明当前代码已经实现的行为
> - AI 中心不是转存中心里的页签；追更同步里用到的 AI 识别和 AI 判定，实际调用的是全局 AI 中心配置

## 1. 先理解转存中心到底管什么

当前转存中心不是单一的“转存一下”按钮，而是一条完整链路：

1. 在 `网盘账号` 里配置真正执行转存的百度/夸克账号
2. 在 `批量转存` 里从系统消息中筛出可处理的源链，创建批次，执行转存、分享、校验、回写
3. 对需要长期跟踪的资源，从批次项转成 `追更同步`
4. 对需要给前台展示的资源，进入 `运营发布`

可以把这 4 个页签理解成：

- `网盘账号`：解决“用哪个账号转、默认保存到哪、默认怎么分享”
- `批量转存`：解决“把现有链接批量转进自己的网盘并生成新分享”
- `追更同步`：解决“这条资源后续更新了没有，要不要继续同步”
- `运营发布`：解决“哪些资源正在前台运营、如何复发、如何下线、如何回收”

推荐使用顺序通常是：

1. 先配账号
2. 再做首轮批量转存
3. 成功项按需转为追更任务
4. 需要对外展示的再纳入运营发布

## 2. 当前页面结构总览

### 2.1 网盘账号

用于维护目标网盘账号。

当前前台只开放两个平台：

- `百度网盘`
- `夸克网盘`

### 2.2 批量转存

这一页实际上包含两块：

- `手动批量转存`
- `批次历史`

也就是说，筛资源、建批次、看执行明细、失败重试、发布到前台、转为追更任务，都在这一页完成。

### 2.3 追更同步

这一页只管理“已经纳入跟踪”的资源，不会自动把全站资源都变成追更任务。

当前追更任务来源是：

- 从 `批量转存 -> 批次详情 -> 转为追更任务`
- 支持批量转为追更

### 2.4 运营发布

这一页已经是“资源表”模式，而不是简单日志。

同一资源再次发布到前台时，当前实现会尽量复用同一条资源记录，只更新：

- 最近发布时间
- 发布次数
- 当前链接状态
- 生命周期状态

## 3. 网盘账号

入口：`资源运营 -> 转存中心 -> 网盘账号`

### 3.1 字段含义

当前账号表单字段如下：

| 字段 | 说明 |
| --- | --- |
| `平台` | 当前支持百度网盘、夸克网盘 |
| `账号名称` | 后台用于识别这个账号的名字，例如“夸克主号 A” |
| `认证方式` | 当前前端固定为 `cookie` |
| `Cookie` | 真正执行网盘操作所需的凭据 |
| `默认保存目录` | 这个账号转存时默认使用的根目录 |
| `默认分享方式` | `转存后继续分享` 或 `仅转存不公开` |
| `默认提取码` | 需要私密分享时可用 |
| `默认有效天数` | 分享有效期，允许留空 |
| `启用账号` | 只有启用账号才会进入目标账号选择和实际执行 |
| `设为默认` | 同平台有多个启用账号时，预览页会优先选它 |

### 3.2 列表里几个状态是什么意思

- `启用 / 停用`
  - 决定这个账号能不能参与真实批次执行
- `Cookie 已配置 / 缺少 Cookie`
  - 只是看凭据有没有存，不代表一定可用
- `最近校验通过 / 最近校验失败 / 未校验`
  - 是账号连通性检查结果，不是资源链接有效性检查结果

### 3.3 校验按钮到底做什么

`校验` 按钮只验证：

- 当前 Cookie 是否还能正常操作该网盘账号

不会做这些事：

- 不会扫描你所有待转存资源
- 不会提前判断某条原链是否有效
- 不会创建目录、不会分享、不会改写数据

### 3.4 使用建议

- 每个平台至少准备 1 个启用账号
- 更新 Cookie 后，先点一次 `校验`
- 如果一个平台没有启用账号，预览仍然能搜到该平台资源，但这类资源不能真正进入可执行批次

## 4. 批量转存

入口：`资源运营 -> 转存中心 -> 批量转存`

### 4.1 这一页由哪几部分组成

#### 上半部分：手动批量转存

用于：

- 打开“选择资源”弹窗
- 筛选候选源链
- 选择每个平台实际用哪个账号执行
- 创建批次

#### 下半部分：批次历史

用于：

- 查看已创建批次
- 打开批次明细
- 查看执行终端
- 重试失败项
- 发布到前台
- 转为追更任务
- 删除批次

### 4.2 选择资源弹窗怎么工作

#### 4.2.1 当前前台真正开放的筛选条件

当前前台只开放了这几个筛选项：

- `最近消息数`
- `关键词搜索`
- `网盘平台`
- `链接状态`

当前前台没有开放这些后端能力：

- `时间范围选择`
- `最早优先 / 最新优先切换`

也就是说，当前前台固定使用：

- `selection_mode = recent_messages`
- `direction = newest_first`

#### 4.2.2 不输入关键词时的扫描范围

如果关键词为空，系统会：

1. 从带链接的消息里按 `消息 ID 倒序` 取最近 N 条
2. 从这些消息里抽出网盘链接
3. 以 `link_target_id` 去重
4. 生成预览列表

默认值是：

- 最近 `200` 条消息
- 默认平台选中 `夸克网盘`
- 链接状态默认 `全部`

#### 4.2.3 输入关键词后会发生什么

这是当前实现里非常重要的一点：

- 只要 `关键词` 不为空，预览就会切换成“全库历史搜索”
- 此时不再受“最近消息数”限制

也就是说：

- 不输入关键词：扫最近 N 条消息
- 输入关键词：扫全部历史消息里符合条件的链接

当前界面上的“搜索范围”摘要就是这样显示的：

- 无关键词时：`最近 N`
- 有关键词时：`全库历史`

#### 4.2.4 关键词具体匹配什么

当前代码会匹配这些内容：

- 资源标题 `short_title`
- 最新消息标题 `latest_message_title`
- 最新消息描述 `latest_message_description`
- 作品标题 `work_title`
- 原链接 `original_url`
- 分享码 `share_key`

另外，如果关键词出现在消息标题、消息描述、展示文本里，系统也会把相关 link target 拉出来。

#### 4.2.5 链接状态筛选是什么意思

当前可选：

- `全部`
- `仅正常`
- `排除失效`

它依据的是系统里已有的链接健康状态，不是这次打开弹窗时重新实时校验。

可理解为：

- `全部`：不过滤
- `仅正常`：只要最近健康状态明确是 healthy
- `排除失效`：把明确 invalid 的排掉，unknown 仍然保留

#### 4.2.6 预览列表的一行代表什么

当前一行不是“一条消息”，而是“一条唯一源链”。

因此你会在表格里看到：

- `影响消息数`
- `链接引用数`

它表示这条源链在系统里影响了多少消息和多少引用，而不是单条消息明细。

#### 4.2.7 预览列表当前怎么排序

当前代码里，预览结果在过滤完成后按下面顺序排序：

1. `影响消息数` 从高到低
2. `最新消息时间` 从新到旧
3. `link_target_id` 从小到大

所以它不是单纯“最新消息排最前”，而是优先把影响面更大的源链排前面。

#### 4.2.8 目标账号选择怎么生效

弹窗里每个平台都会显示当前可用账号下拉框：

- 只展示 `启用中` 的账号
- 同平台如果有默认账号，会优先选中默认账号
- 这个选择只影响本次新建批次，不会改掉账号配置本身

示例：

- 你勾了夸克和百度资源
- 夸克选“夸克主号 A”
- 百度选“百度备份号 B”

那么本次批次里：

- 夸克源链会走“夸克主号 A”
- 百度源链会走“百度备份号 B”

### 4.3 创建批次

#### 4.3.1 创建前必须先勾选资源

当前批次只会处理你在预览表里勾选的源链。

正确顺序是：

1. 打开 `选择资源`
2. 搜索并勾选
3. 点 `创建批次`

#### 4.3.2 当前前台默认值

当前前台创建批次时的默认值如下：

| 配置 | 当前默认值 |
| --- | --- |
| 创建后立即入列 | `开启` |
| 最大尝试次数 | `3` |
| 自动重试间隔 | `10 分钟` |
| 目录布局 | `批次归档` |
| 批次目录名 | `剧集` |
| 资源目录模板 | `强混淆乱码模板` |
| 分享层级 | `原分享目录` |

#### 4.3.3 执行策略说明

##### 创建后立即入列

- 开启：创建成功后立刻进入 worker 队列
- 关闭：先保存成草稿，之后手动启动

##### 最大尝试次数

单条批次项最多自动尝试多少次。

当前前端允许范围：

- `1 ~ 10`

##### 自动重试间隔

可选值：

- 不自动重试
- 1 分钟
- 5 分钟
- 10 分钟
- 30 分钟
- 60 分钟

含义：

- 失败项如果还没超过最大尝试次数，会按这个间隔再次入队
- 设为 0 时，不自动重试，只能人工重试

### 4.4 目录与分享规则

#### 4.4.1 目录布局

当前有两种：

| 选项 | 含义 |
| --- | --- |
| `独立目录` | 每条资源直接落在账号根目录下 |
| `批次归档` | 先进入批次目录，再进入每条资源目录 |

##### 例子一：独立目录

假设：

- 默认保存目录：`TG`
- 资源目录名：`tg-transfer-13-18-the-show-s01e08-1080p`

那么目标路径类似：

```text
TG/tg-transfer-13-18-the-show-s01e08-1080p/<原分享目录或文件>
```

##### 例子二：批次归档

假设：

- 默认保存目录：`TG`
- 批次目录名：`剧集`
- 资源目录名：`tg-transfer-13-18-the-show-s01e08-1080p`

那么目标路径类似：

```text
TG/剧集/tg-transfer-13-18-the-show-s01e08-1080p/<原分享目录或文件>
```

#### 4.4.2 资源目录模板

当前前端提供 4 种预设：

| 预设 | 实际模板 | 说明 |
| --- | --- | --- |
| 强混淆乱码模板 | `{title_masked_mix}` | 把标题稳定映射成强混淆目录名 |
| 中文混淆标题模板 | `{title_masked_cn}` | 用中文风格混淆，兼容性更高 |
| 自动编码目录 | `tg-transfer-{batch_id}-{item_id}-{title_slug}` | 技术型目录名 |
| 自定义模板 | 手填 | 支持变量 |

自定义模板支持的变量有：

- `{title}`
- `{title_slug}`
- `{title_masked_cn}`
- `{title_masked_mix}`
- `{platform}`
- `{batch_id}`
- `{item_id}`
- `{share_key}`
- `{date}`

#### 4.4.3 模板的两个重要规则

##### 规则一：目录段会自动做安全清洗

当前后端会自动：

- 去掉非法路径字符
- 压缩空白
- 截断到合理长度
- 清理头尾的空格、点、下划线、连字符

单个目录段最终最大长度是：

- `96` 个字符

##### 规则二：如果模板里没有唯一标识，系统会自动补 `__i{item_id}`

当前后端把 `{item_id}` 和 `{share_key}` 视为“唯一性令牌”。

如果你的模板里没有这两个令牌中的任意一个，系统会自动在末尾补：

```text
__i{item_id}
```

例如模板：

```text
{date}-{title_slug}
```

最终可能落成：

```text
20260416-the-show-s01e08__i18
```

这样做是为了避免目录撞名。

#### 4.4.4 分享层级

当前有两种：

| 选项 | 代码值 | 当前真实行为 |
| --- | --- | --- |
| `原分享目录` | `content_root` | 优先分享资源目录里“唯一的顶层目录或文件”；如果不唯一，自动回退到资源目录 |
| `资源目录` | `resource_dir` | 直接分享整个资源目录 |

##### 例子一：选择 `原分享目录`

假设转存后资源目录结构是：

```text
TG/剧集/tg-transfer-13-18-the-show/
  └── 月鳞绮纪(2026) 更23集/
```

因为资源目录下只有 1 个顶层目录，所以最终分享的是：

```text
月鳞绮纪(2026) 更23集/
```

##### 例子二：仍然选择 `原分享目录`，但顶层不唯一

如果资源目录结构是：

```text
TG/剧集/tg-transfer-13-18-the-show/
  ├── S01/
  ├── 海报.jpg
  └── 字幕/
```

因为顶层有多项，所以不会强行分享其中一项，而是自动回退为分享：

```text
tg-transfer-13-18-the-show/
```

##### 例子三：选择 `资源目录`

无论资源目录下有几项，最终都直接分享资源目录本身。

#### 4.4.5 当前页面里的“路径预览”怎么看

创建批次弹窗里的“路径预览”会展示两条：

- `转存路径`
- `创建分享`

它的作用是让你在创建前先看明白：

- 文件最终落到哪里
- 分享的是资源目录还是原分享目录

### 4.5 批次执行后怎么看

#### 4.5.1 批次状态

当前批次状态包括：

- `草稿`
- `执行中`
- `已停止`
- `已完成`
- `部分失败`
- `全部失败`

#### 4.5.2 批次项状态

当前批次项会展示三组关键信息：

- 转存状态
- 校验状态
- 回写状态

你在明细表里会看到例如：

- `执行中 / 有效 / 已回写`
- `失败 / 待校验 / 待回写`

#### 4.5.3 执行终端里会出现哪些阶段

当前执行日志会按阶段输出，例如：

- `transfer`：转存
- `share`：创建分享
- `validate`：校验新分享
- `replace`：回写旧链接
- `publish`：发布到前台
- `finish`：完成

#### 4.5.4 批次和明细会不会自动刷新

会。

当前实现是：

- 页面可见时
- 如果有 `执行中` 的批次
- 批次列表和打开的批次详情会每 `4 秒` 自动轮询一次

所以运行中的批次通常不用手动刷新整页。

#### 4.5.5 “新分享链接”和“当前生效链接”的区别

##### 新分享链接

表示这次转存刚创建出来的新网盘分享。

##### 当前生效链接

表示系统已经回写成功、当前真正写回到系统里的链接目标。

这两个字段不一定完全等价：

- 如果新分享创建成功，但回写还没完成，那么只有“新分享链接”
- 如果回写完成，“当前生效链接”就代表系统内真正生效的那条链接

#### 4.5.6 批次详情里的操作按钮

##### 批次级

- `刷新明细`
- `停止批次`
- `重试全部失败项`
- `重试所选失败项`
- `批量发布到前台`
- `批量转为追更`

##### 单条批次项

- `立即重试`
- `发布到前台`
- `转为追更任务`

#### 4.5.7 日志清理有两种，不要混淆

当前执行终端支持两种“清理”：

##### 清空当前显示

- 只影响你当前终端视图
- 不删数据库日志
- 随时可以“显示全部”

##### 清理后端日志

- 会删除数据库里的批次执行日志和回写日志
- 不删除批次本身
- 不删除网盘目录
- 不删除前台消息

### 4.6 从批次发布到前台

批次项点 `发布到前台` 时，当前代码会优先使用下列链接来源：

1. `已回写的新链接`
2. `新分享链接`
3. `原始链接`

表单默认会自动带出：

- 标题
- 描述
- 标签

这些默认值主要来自：

- 批次项标题
- 批次项保存的来源消息快照

发布成功后会发生两件事：

1. 真正往前台消息表里发布一条新消息
2. 同时写入一条“运营发布资源记录”

### 4.7 删除批次会删什么，不会删什么

当前代码里，删除批次会删除：

- 批次记录
- 批次项记录
- 执行日志
- 回写日志

不会删除：

- 原始消息
- 已经转存到网盘里的目录
- 已经生成的新分享
- 已发布到前台的资源
- 运营发布资源记录

所以删除批次的正确理解是：

- 清理系统里的这次任务记录

不是：

- 回收网盘空间

## 5. 追更同步

入口：`资源运营 -> 转存中心 -> 追更同步`

### 5.1 追更任务从哪里来

当前不是全站自动生成，而是从转存成功项手动纳入。

来源：

- `批次详情 -> 单条转为追更任务`
- `批次详情 -> 批量转为追更`

也就是说，追更同步管理的是“你已经认可、并且希望继续维护”的资源。

### 5.2 任务创建后会保存哪些关键上下文

当前追更任务会保存这些核心信息：

- 当前原链 `source_url`
- 当前新分享 `current_share_url`
- 目标账号
- 固定资源目录 `fixed_save_path`
- 目录布局 `transfer_layout`
- 资源目录模板
- 分享层级 `share_target_mode`
- 来源消息快照 `source_message_snapshot`
- 如果已有作品归并结果，还会保存 `work_id / work_title`

这也是为什么追更同步不是“重新建一个新资源”，而是“继续维护已有资源目录”。

- 最长 `7 天`

详情页 `追更设置` 可以修改。

### 5.5 追更设置里这几个参数分别是什么意思

#### 检查间隔

控制任务多久自动巡检一次。

#### 候选回看范围 `lookback_days`

表示这次巡检回头看最近多少天内出现的新消息线索。

当前允许范围：

- `1 ~ 90` 天

默认：

- `30` 天

#### 最多召回候选 `max_recall_candidates`

先在站内召回多少条候选链接，进入候选池。

当前允许范围：

- `1 ~ 30`

默认：

- `12`

#### 最多评估候选 `max_judge_candidates`

从召回候选里，最多拿多少条交给 AI 或回退规则做“是否值得提升为候选”判断。

当前允许范围：

- `1 ~ 12`
- 且不能大于 `max_recall_candidates`

默认：

- `6`

### 5.6 AI 识别身份是怎么工作的

详情页里的 `AI 识别身份` 卡片，展示的是系统当前为这条追更任务提取出来的“作品身份快照”。

#### 5.6.1 AI 的输入标题用的是哪一个

当前代码里，识别输入标题来自任务当前的 `resource_title`。

这个标题的解析顺序是：

1. `source_message_snapshot.title`
2. `work_title`
3. `topic_title`
4. `task_name`

详情页里会明确显示：

- `识别输入标题：xxx`

也就是说，前台看到的这条说明，就是这次识别真正用到的标题。

#### 5.6.2 AI 会产出什么

当前会保存这些字段：

- `core_title`
- `aliases`
- `release_year`
- `season`
- `latest_episode`
- `content_type`
- `search_queries`
- `reason`
- `source`
- `used_model`
- `updated_at`

#### 5.6.3 AI 会不会每次都重新跑

不会无脑每次都跑。

当前逻辑是：

- 如果已经有 `identity_snapshot.core_title`
- 并且上次识别时记录的 `resource_title` 和当前标题完全相同
- 就直接复用已有身份快照

只有当“当前资源标题变了”时，才会重新提取。

#### 5.6.4 同步成功后为什么身份可能会更新

因为追更同步成功后，系统会把本次同步使用的来源消息快照写回任务。

如果这次同步后的标题已经变成新一期标题，例如：

- 原来：`月鳞绮纪(2026) 60FPS S01E01 - E22`
- 同步后来源消息标题变成：`月鳞绮纪‎ (2026) 更23集`

那么成功回调里会重新检查身份快照，必要时立即重建。

### 5.7 候选判定到底是怎么来的

当前候选判定分成 3 步：

#### 第一步：先构造召回关键词

关键词来自身份快照中的：

- `search_queries`
- `aliases`
- `core_title`
- `work_title`
- `topic_title`

最终会去重并压到最多 4 个查询词。

#### 第二步：做两路召回，然后合并

##### 路一：按作品归并结果召回

如果这条追更任务已经绑定了 `work_id`，系统会：

- 在同平台内
- 找同 `work_id`
- 且最近 `lookback_days` 天内出现过的候选源链

##### 路二：按身份关键词召回

系统还会：

- 在同平台内
- 看最近 `lookback_days` 天的最新消息引用
- 用召回关键词去匹配

匹配范围包括：

- 最新消息标题
- 最新消息描述
- 链接展示文本 `display_text`

#### 第三步：AI 做候选裁决

合并后的候选会按最近消息时间从新到旧排序，最多保留：

- `max_recall_candidates`

然后最多取前：

- `max_judge_candidates`

交给 AI 逐条判断。

当前这一步 AI 输入的是：

- 当前追踪资源的身份信息
- 候选标题 `candidate.title`

当前版本不会把这些字段继续喂给 AI 判定：

- `display_text`
- `description`
- `latest_message_time`

这些字段主要用于召回和页面展示，不参与当前 AI 判定 prompt。

#### 5.7.1 AI 判定什么才算命中候选

当前规则是：

- 先判断是不是同一作品
- 只有“同一作品”且“明显更新更晚”时，`should_promote` 才能为 `true`

当前更偏向用“集数推进”作为是否更新的主信号。

#### 5.7.2 召回到了但不一定会留下

候选即使被 AI 判成值得提升，也还会再做一次链接有效性校验。

如果校验结果是：

- `invalid`
- `error`

那么这条候选不会被保留。

#### 5.7.3 已有候选不健康时会怎样

当前实现已经支持自动处理：

- 如果之前存着一条候选，但这次校验它已经失效或异常
- 系统会自动移除这条旧候选

所以“候选不健康仍一直留着不动”并不是当前逻辑。

### 5.8 详情页里的几个卡片怎么理解

#### 5.8.1 追更设置

用于改：

- 检查间隔
- 回看天数
- 候选召回上限
- 候选评估上限

#### 5.8.2 AI 识别身份

用于看：

- 当前系统认为这条资源的核心剧名是什么
- 年份、季、当前集数识别成了什么
- 召回关键词用了什么
- 这次识别输入标题到底是什么
- 是 AI 识别还是 fallback 规则识别

#### 5.8.3 候选判定

用于看：

- 这次总共召回了多少候选
- 最多评估多少条
- AI 是否认为“是同作品”
- AI 是否认为“更晚更新”
- 当前集数和候选集数分别是多少
- 实际使用了哪些召回查询词

#### 5.8.4 候选来源

用于看：

- 当前被系统保留的候选标题
- 候选出现时间
- 候选链接

并可执行：

- `进入人工确认`
- `清空候选`

#### 5.8.5 执行终端

用于看：

- 巡检何时开始
- 原链校验结果
- 新分享校验结果
- 是否生成身份快照
- 是否发现候选
- 是否创建了同步批次
- 是否把绑定的前台发布记录更新到了最新分享

同样支持：

- 只清空当前显示
- 清理后端日志

### 5.9 当前三条规则分别是什么

详情页 `规则处理` 现在已经收敛为 3 条规则。

#### 规则一：安全同步

适用场景：

- 当前原链仍然可用
- 或者只是当前对外分享异常，想刷新分享

执行方式：

- 来源固定用 `当前原链`
- `sync_mode = standard`
- 不要求手动勾选文件
- 复用当前已有资源目录
- 不主动清空旧内容

补充说明：

- 前端发起时默认会带 `reuse_existing_share_if_valid = true`
- 也会带 `update_publish_record = true`
- 但“复用旧分享”只有在任务分享层级本来就是 `资源目录` 时才有机会生效
- 如果这次同步生成了新的分享，并且这条追更任务绑定了运营发布记录，系统会自动把运营发布记录的前台链接更新到最新分享

#### 规则二：全量替换

适用场景：

- 你已经确认原内容结构变化很大
- 或者需要彻底清空旧资源目录再重建

执行方式：

- 进入高级人工处理弹窗
- 选择 `当前原链` 或 `候选原链`
- 手动勾选目录/文件
- 勾选确认框后才能提交

风险点：

- 会先清空当前资源目录
- 如果导入失败，目录可能暂时是空的

#### 规则三：候选人工确认

适用场景：

- 系统已经发现候选原链
- 但不想直接把新候选整包写进现有资源目录

执行方式：

- 默认打开高级人工处理弹窗
- 来源优先切到 `候选原链`
- 默认建议 `增量追加`
- 需要你先浏览目录，再勾选要导入的内容

### 5.10 高级人工处理弹窗怎么用

弹窗标题是：

- `高级处理：同步到现有资源目录`

它不是新建一个全新资源，而是把你选中的内容同步进当前任务的固定资源目录。

#### 5.10.1 可选来源

- `当前原链`
- `候选原链`

#### 5.10.2 可选同步模式

- `增量追加`
- `全量替换`

注意：

- 高级弹窗里没有“手动标准同步”
- 因为标准同步本来就是整包同步当前原链，不需要勾选文件

#### 5.10.3 目录浏览和选择

弹窗支持：

- 逐层进入子目录
- 面包屑返回上层
- 刷新当前目录
- 全选当前目录
- 清空选择

只有在以下模式才允许提交：

- `增量追加`
- `全量替换`

而且：

- `selected_entries` 不能为空
- `replace_all` 必须手动勾选确认框

#### 5.10.4 增量追加和全量替换的区别

##### 增量追加

- 把你勾选的目录或文件继续导入现有资源目录
- 不主动删除旧内容

##### 全量替换

- 先清空当前资源目录
- 再导入你勾选的目录或文件

### 5.11 追更列表和详情会不会自动刷新

会。

当前实现是：

- 页面可见
- 且当前 tab 处于激活状态
- 只要列表中存在 `queued / checking / sync_queued`
- 或者你打开的详情正处于这些临时状态

系统就会每 `4 秒` 自动轮询刷新。

### 5.12 删除追更任务会删什么

当前会删除：

- 追更任务本身
- 追更任务日志

不会删除：

- 资源目录
- 当前分享
- 原始消息
- 前台运营记录

## 6. 运营发布

入口：`资源运营 -> 转存中心 -> 运营发布`

### 6.1 当前页的定位

这一页不是“发布动作日志”，而是“资源运营表”。

当前表格按资源聚合展示：

- 同一资源重复发布时，不再新增新的主表行
- 而是更新最近发布时间、发布次数、链接状态等信息

### 6.2 当前支持的查询方式

#### 搜索

搜索会匹配：

- 标题
- 描述
- 标签
- 平台
- 操作人
- 前台链接
- 原链
- 当前分享
- 发布规则摘要

#### 平台筛选

当前支持：

- 百度网盘
- 夸克网盘

#### 范围筛选

当前有三档：

- `活跃`
- `已归档`
- `全部`

说明：

- `活跃` 只看仍在运营中的资源
- `已归档` 包含仅归档、已下线、已回收等非活跃资源
- `全部` 看全部生命周期状态

#### 排序

当前默认排序是：

- `最近发布时间` 倒序

表格还支持按这些字段排序：

- 平台
- 点击量
- 发布次数

### 6.3 表格里的链接标签怎么理解

当前一条资源可能展示三路链接：

- `原链`
- `新分享`
- `前台`

每个标签都支持：

- 左键直接打开
- 右键菜单访问 / 复制 / 查看目录

状态会显示为：

- `有效`
- `失效`
- `存疑`
- `未知`
- `异常`

### 6.4 当前有哪些操作按钮

单条资源支持：

- `发布到前台`
- `校验三路链接`
- `重建分享`
- `编辑发布内容`
- `发布规则`
- `退出运营`

批量支持：

- `批量发布到前台`
- `批量校验链接`
- `批量重建分享`
- `批量退出运营`

### 6.5 手动新建发布

入口：

- `运营发布 -> 手动新建发布`

当前需要填写：

- 平台
- 分享链接
- 标题
- 描述
- 标签

适用场景：

- 不是从当前批次来的资源
- 已经有现成分享链接，只想纳入前台运营

### 6.6 编辑发布内容

编辑的是当前运营资源记录本身，包括：

- 当前前台对外链接 `source_url`
- 标题
- 描述
- 标签

这不是改原始消息，也不是改批次项。

### 6.7 校验三路链接

当前校验按钮会尽量检查：

- 原链
- 当前新分享
- 当前前台链接

方便你一次看清这条资源现在到底哪一路有问题。

### 6.8 重建分享

适用前提：

- 这条资源允许重建分享 `can_refresh_share = true`

作用：

- 从现有资源目录重新创建新分享
- 同步更新当前运营资源记录

### 6.9 发布规则

当前发布规则字段很简单：

- 是否启用
- 哪几天执行
- 每天几点执行
- 时区固定为 `Asia/Shanghai`

页面上只需要填：

- 星期
- `HH:MM`

示例：

- 周一、周三、周五
- `09:00`

表示：

- 每周一、三、五上午 9 点按当前资源内容重新发布一次

### 6.10 退出运营三种模式

当前退出运营不会直接把这条资源主记录物理删除，而是按模式修改生命周期。

#### 模式一：仅归档

效果：

- 从活跃列表移走
- 保留前台消息
- 保留网盘资源
- 保留当前分享

适用：

- 暂时不重点运营，但还不想动前台和网盘资源

#### 模式二：下线前台

效果：

- 删除前台消息
- 清理前台相关绑定
- 保留网盘资源
- 保留当前分享资源记录

适用：

- 不想让前台继续展示
- 但资源目录还想留着，后面可能再用

#### 模式三：回收资源

效果：

- 删除前台消息
- 清理绑定
- 暂停相关追更绑定
- 尝试回收网盘资源目录
- 清掉当前分享

适用：

- 真正想释放网盘容量
- 这条资源已经不打算继续运营

### 6.11 退出运营后还能在哪里看到

只要不是物理删除主记录，资源仍然会保留在运营表里。

查看方式：

- 切到 `已归档`
- 或切到 `全部`

## 7. 推荐操作示例

### 7.1 示例一：先做一批首轮转存，再纳入追更

场景：

- 你要处理最近更新的一批夸克剧集资源

建议步骤：

1. 在 `网盘账号` 配好夸克账号，默认保存目录例如 `TG/剧集`
2. 去 `批量转存 -> 选择资源`
3. 不输入关键词时，先扫最近 `200` 条消息
4. 如果要精确找某部剧，再输入剧名，此时会切到全库历史搜索
5. 勾选目标资源
6. 创建批次，保持默认：
   - 立即入列
   - 最大尝试 3
   - 自动重试 10 分钟
   - 批次归档
   - 资源目录强混淆
   - 分享层级原分享目录
7. 在批次详情里观察 `转存 -> 分享 -> 校验 -> 回写`
8. 成功后，对需要长期跟踪的条目点 `转为追更任务`
9. 需要上前台的条目点 `发布到前台`

### 7.2 示例二：候选出现后做人工确认

场景：

- 当前追更任务已经发现候选原链
- 你不想直接整包覆盖旧目录

建议步骤：

1. 打开 `追更同步` 详情
2. 在 `AI 识别身份` 看核心剧名和当前集数是否正确
3. 在 `候选判定` 看是否已经判断为同作品且更晚更新
4. 在 `候选来源` 点 `进入人工确认`
5. 来源选 `候选原链`
6. 模式先选 `增量追加`
7. 浏览目录，只勾选本次真正想同步的目录或文件
8. 提交后会创建一条 `follow_sync` 批次
9. 同步成功后，任务会更新：
   - 当前原链
   - 当前新分享
   - 最近同步批次
   - 如绑定了运营发布记录，还会更新前台使用的链接

### 7.3 示例三：不再运营并回收容量

场景：

- 某条老资源不再需要占用网盘容量

建议步骤：

1. 去 `运营发布`
2. 选中这条资源
3. 点 `退出运营`
4. 选择 `回收资源`
5. 确认后，系统会：
   - 下线前台
   - 清理绑定
   - 尝试回收网盘资源目录

如果你只是想先停止前台展示，不想马上删网盘内容，则选：

- `下线前台`

## 8. 常见问题

### 8.1 当前前台批量转存支持时间范围吗

后端请求模型支持，但当前前台没有开放这个入口。

当前前台固定是：

- 最近消息模式
- 最新优先

### 8.2 关键词搜索时，“最近消息数”还生效吗

不生效。

当前代码里，只要关键词不为空，就会切换成全库历史搜索。

### 8.3 预览表为什么不是单纯按最新时间排序

因为当前排序逻辑优先看：

1. 影响消息数
2. 最新消息时间
3. link_target_id

这样更容易把“影响范围更大”的源链排到前面。

### 8.4 追更同步会自动换候选原链吗

当前不会完全自动闭环。

已经自动完成的部分有：

- 巡检原链
- 巡检当前分享
- AI 识别作品身份
- 召回并判定候选
- 候选失效时自动移除

仍然需要人工确认的部分主要是：

- 候选原链导入到现有资源目录
- 高风险全量替换

### 8.5 规则一会不会清空旧目录

不会。

规则一是：

- 复用现有资源目录
- 不主动清空旧内容

### 8.6 高级人工处理里的“增量追加”和“全量替换”会同步到哪里

都会同步到这条追更任务当前绑定的：

- `fixed_save_path`

也就是同一个既有资源目录。

区别只在于：

- 增量追加：不删旧内容
- 全量替换：先清空再导入

### 8.7 批次详情和追更终端里的“清空显示”和“清理后端日志”有什么区别

#### 清空显示

- 只影响当前页面显示
- 不删数据库

#### 清理后端日志

- 真正删除数据库日志
- 不删任务本身

### 8.8 运营发布里重复发布同一资源，会新增很多重复行吗

当前主表不会无限堆重复主行。

同一资源再次发布时，当前资源表会尽量聚合到同一条资源记录上，重点更新：

- 最近发布时间
- 发布次数
- 当前链接状态

### 8.9 删除批次、删除追更任务、退出运营，这三者有什么本质区别

#### 删除批次

- 只清理批次及其日志

#### 删除追更任务

- 只清理追更任务及其日志

#### 退出运营

- 改的是运营资源生命周期
- 可选择是否下线前台、是否回收网盘资源

### 8.10 当前转存中心里有 AI 中心页签吗

没有。

AI 中心是独立模块。

转存中心当前只是消费 AI 中心能力，典型位置在：

- `追更同步 -> AI 识别身份`
- `追更同步 -> 候选判定`

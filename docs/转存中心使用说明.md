# 转存中心使用说明

> 适用范围
>
> - 对应后台 `资源运营 -> 转存中心`
> - 当前真实页签只有 4 个：`网盘账号`、`批量转存`、`追更同步`、`运营发布`
> - AI 识别与 AI 判定统一走 `AI 中心` 配置，转存中心不再单独维护一套 AI 参数
> - 本文只说明当前代码已经实现的行为，不写未落地设计

## 1. 转存中心整体是做什么的

转存中心不是一个单独的“转存一下”按钮，而是一条完整链路：

1. 在 `网盘账号` 里配置真正执行转存的百度网盘 / 夸克网盘账号。
2. 在 `批量转存` 里从系统消息中筛选源链接，创建批次，执行转存、创建新分享、校验新分享、回写系统里的旧链接引用。
3. 对需要长期跟踪更新的资源，从批次项转为 `追更同步` 任务。
4. 对需要对外展示的资源，发布到 `运营发布`。

推荐使用顺序：

1. 先配置并校验网盘账号。
2. 再创建首轮批量转存批次。
3. 成功项按需转为追更同步任务。
4. 需要前台展示的资源再纳入运营发布。

## 2. 网盘账号

入口：`资源运营 -> 转存中心 -> 网盘账号`

当前前端只支持两种平台：

- `百度网盘`
- `夸克网盘`

账号的核心作用是决定：

- 用哪个账号执行转存。
- 默认保存到哪个根目录。
- 默认是否公开分享。
- 默认分享提取码和有效期。

列表里的几个状态含义：

- `启用 / 停用`：决定这个账号能不能参与新批次和追更同步。
- `Cookie 已配置 / 缺少 Cookie`：只表示凭证是否已填写，不代表一定可用。
- `最近校验通过 / 最近校验失败 / 未校验`：表示账号连通性检查结果，不是资源链接健康状态。

`校验` 按钮只做账号级连通性验证，不会：

- 提前扫描你的待转存资源。
- 创建目录或创建分享。
- 修改任何消息、链接、发布记录。

## 3. 批量转存

入口：`资源运营 -> 转存中心 -> 批量转存`

这一页分成两块：

- `手动批量转存`：筛资源、勾选资源、创建批次。
- `批次历史`：看批次执行结果、失败重试、发布到前台、转为追更、删批次、清日志。

### 3.1 选择资源弹窗怎么工作

当前前端固定使用：

- `selection_mode = recent_messages`
- `direction = newest_first`

也就是消息扫描顺序默认按“最新消息在前”。

当前弹窗开放的筛选项：

- 最近消息数
- 关键词
- 网盘平台
- 链接状态

#### 3.1.1 不输入关键词时

系统会：

1. 从带链接的消息里按最新到最旧取最近 N 条消息。
2. 从这些消息里抽出网盘链接。
3. 以 `link_target_id` 去重。
4. 生成可勾选的源链接列表。

当前前端默认值：

- 最近消息数：`200`
- 默认平台：`夸克网盘`
- 链接状态：`全部`

#### 3.1.2 输入关键词时

只要关键词不为空，系统会切换到“全历史搜索”：

- 不再受“最近消息数”限制。
- 会先把候选源链接收集出来，再按关键词过滤。
- 关键词会匹配资源标题、最新消息标题、最新消息描述、作品标题、原链接、分享码等字段。

所以可以这样理解：

- 不输关键词：扫最近 N 条消息。
- 输入关键词：按关键词扫全历史。

#### 3.1.3 预览列表里一行代表什么

一行代表的是“一个唯一源链接”，不是“一条消息”。

因此你会看到这些统计：

- `影响消息数`：这条源链接影响了多少条消息。
- `引用次数`：这条源链接在系统消息引用里一共出现了多少次。
- `最新消息时间`：这条源链接最近一次出现在消息里的时间。

#### 3.1.4 预览列表怎么排序

当前实现里，候选结果聚合后按下面顺序排序：

1. `影响消息数` 从高到低。
2. `最新消息时间` 从新到旧。
3. `link_target_id` 从小到大。

所以它不是纯粹的“最新时间排第一”，而是优先把影响范围更大的源链接排前面。

#### 3.1.5 链接状态筛选是什么意思

可选值：

- `全部`
- `仅正常`
- `排除失效`

这里使用的是系统里最近一次已知的链接健康状态，不是你打开弹窗时重新实时校验。

含义可以理解成：

- `全部`：不过滤。
- `仅正常`：只保留最近状态明确为健康的链接。
- `排除失效`：明确失效的去掉，未知状态仍保留。

### 3.2 创建批次时会带哪些默认值

当前前端创建批次默认值如下：

| 配置 | 当前默认值 |
| --- | --- |
| 创建后立即入列 | `开启` |
| 最大尝试次数 | `3` |
| 自动重试间隔 | `10 分钟` |
| 目录布局 | `批次归档` |
| 批次目录名 | `剧集` |
| 资源目录模板 | `强混淆乱码模板` |
| 分享层级 | `原分享目录` |

如果你是直接调 API 而不是走前端，后台还会有自己的兜底值；但日常从页面操作时，以上就是当前实际默认体验。

### 3.3 目录与分享规则

批量转存真正会生成两层概念：

- `资源目录`：系统在目标账号里实际落地的目录。
- `对外分享目标`：最后拿哪一层去创建新分享。

#### 3.3.1 目录布局

有两种：

| 选项 | 含义 |
| --- | --- |
| `独立目录` | 每条资源直接落在账号根目录下 |
| `批次归档` | 先进入一个批次目录，再进入每条资源目录 |

例子：

- 账号默认保存根目录是 `TG`
- 目录布局选 `批次归档`
- 批次目录名选 `剧集`
- 当前资源目录名生成后是 `月鳞绮纪__i18`

则最终资源目录路径会类似：

`TG/剧集/月鳞绮纪__i18`

如果改成 `独立目录`，则路径会类似：

`TG/月鳞绮纪__i18`

#### 3.3.2 资源目录名怎么来

当前前端用的是“模板预设 + 自定义模板”模式，实际提交时会走 `custom` 模板渲染。

你在界面上看到的几个预设，本质上是不同模板：

- 强混淆乱码模板
- 中文混淆标题模板
- 自动编码目录
- 自定义模板

这些模板会生成真正的资源目录名。

#### 3.3.3 分享层级怎么理解

当前有两个值：

| 选项 | 含义 |
| --- | --- |
| `原分享目录` | 如果资源目录下只有一个顶层目录或文件，就直接分享它；否则自动回退为分享资源目录 |
| `资源目录` | 永远分享整个资源目录 |

例子 1：

- 资源目录是 `TG/剧集/月鳞绮纪__i18`
- 目录里面只有一个顶层目录 `月鳞绮纪(2026) S01`

这时如果选择 `原分享目录`，最终会直接分享 `月鳞绮纪(2026) S01` 这一层。

例子 2：

- 资源目录里面同时有 `月鳞绮纪(2026) S01`
- 还有 `海报.jpg`

这时顶层不再唯一，系统会自动回退为分享整个 `月鳞绮纪__i18` 资源目录。

### 3.4 批次执行时到底做了什么

单个批次项的标准执行流程是：

1. 把源链接内容转存到目标账号的资源目录。
2. 基于资源目录或原分享目录创建新的网盘分享。
3. 校验新分享是否有效。
4. 用新分享链接回写系统里的旧链接引用。

这里的“回写”是系统内数据回写，主要影响：

- `link_targets`
- `message_link_refs`
- `messages.links`
- 相关点击事件引用

它不是去编辑 Telegram 远端原消息。

### 3.5 批次历史里可以做什么

当前批次详情支持：

- 查看每个批次项的执行状态。
- 查看执行终端日志和替换日志。
- 失败项重试。
- 从成功项发布到前台。
- 从成功项转为追更同步任务。
- 删除批次。
- 清空后端日志。

关于日志清理：

- `仅清当前显示`：只是前端本地隐藏，数据库日志还在。
- `清空后端日志`：会真正删除数据库里的执行日志和替换日志。

## 4. 追更同步

入口：`资源运营 -> 转存中心 -> 追更同步`

追更同步只管理“已经纳入长期跟踪”的资源，不会自动把所有转存成功资源都变成追更任务。

当前任务来源是：

- 从 `批量转存 -> 批次详情 -> 转为追更任务`
- 支持批量转为追更

### 4.1 创建追更任务时会保存什么

从批次项转为追更任务时，系统会保存这些关键数据：

- 当前追踪平台
- 当前原链
- 当前分享链接
- 资源目录固定路径
- 首次创建时的目录策略和分享层级
- 来源消息快照 `source_message_snapshot`
- 候选巡检参数
- 绑定的运营发布记录

其中 `source_message_snapshot` 很重要，它保存了这条任务当前认定的来源消息标题、描述、时间等信息，后续 AI 识别身份也会基于它。

### 4.2 当前默认巡检参数

当前默认值：

- 巡检间隔：`180 分钟`
- 候选时间范围：`3 天`
- 最多召回候选：`12`
- 最多评估候选：`6`

这四个值支持按任务单独保存。

含义分别是：

- `巡检间隔`：多久自动巡检一次。
- `候选时间范围`：只在最近多少天的消息范围内找候选。
- `最多召回候选`：站内先召回多少条候选链接进入候选池。
- `最多评估候选`：从候选池里最多拿多少条去做 AI 判定。

约束关系：

- `最多评估候选` 不能大于 `最多召回候选`

### 4.3 一次巡检的真实流程

追更任务每次巡检时，当前逻辑是：

1. 先校验当前原链是否有效。
2. 再校验当前分享是否有效。
3. 确保任务的作品身份快照存在。
4. 如果任务里已经有已保存候选，先复查这个候选是否仍有效。
5. 再到最近时间范围内召回新的候选原链。
6. 对候选做 AI 判定。
7. 根据结果决定：
   - 记为候选。
   - 自动做同集数处理。
   - 不做任何变更。

### 4.4 候选从哪里找

当前候选召回有两条来源，最后会合并去重：

1. `按作品绑定召回`
2. `按身份关键词召回`

共同约束：

- 只在任务同平台内找，不会跨盘。
- 只在最近 `候选时间范围` 天里找。
- 会排除当前任务自己已经绑定的链接。
- 结果优先按最近消息时间和链接新鲜度排序。

所以不会出现“夸克任务把百度候选拿来替换”的情况。

### 4.5 AI 在追更同步里做什么

当前 AI 分两步：

#### 4.5.1 AI 识别身份

作用是从当前任务的资源标题里提取追更身份，形成 `identity_snapshot`。

这一步主要会产出：

- `core_title`
- `aliases`
- `release_year`
- `season`
- `latest_episode`
- `content_type`
- `search_queries`

系统会优先用当前资源标题作为主输入，目标是把：

- 年份
- 分辨率
- 帧率
- 集数范围
- 演员列表
- 更新文案

这些噪音去掉，只保留作品核心名和可用召回词。

如果 AI 失败，系统会回退到规则兜底识别，不会直接中断整条巡检。

#### 4.5.2 AI 判定候选

作用是判断某条候选是不是同一作品、有没有明显更新、是否应该提升为候选来源。

这一步最多只会评估 `最多评估候选` 条。

AI 判定的重点是：

- 是否同作品。
- 候选集数是否高于当前最新集数。
- 标题语义是否足够可信。

如果 AI 判定失败，也会回退到规则兜底，不会让任务直接报废。

### 4.6 候选什么时候会被记下来

只有满足下面条件，候选才会被保存到任务里：

1. 先通过召回。
2. 再被 AI 或规则判定为可提升。
3. 最后这条候选链接自身还要再次校验为健康。

如果候选链接健康检查不通过，系统会直接丢弃，不会保留一个不健康候选。

如果任务里原来保存过旧候选，巡检时发现这个旧候选已经不健康，也会自动把它移除。

### 4.7 三种规则怎么落地

当前前端围绕三条规则组织操作，目的是把按钮职责拆开，不让入口重叠。

#### 规则一：安全同步

适合场景：

- 当前原链仍可用。
- 或者你只是想刷新现有资源目录和分享。

实际动作：

- 来源固定用 `当前原链`
- 同步模式固定用 `standard`
- 复用现有资源目录
- 不主动删除旧内容
- 不要求人工选目录

这是当前默认推荐路径。

#### 规则二：全量替换

适合场景：

- 你确认当前资源目录已经不可信。
- 或者候选目录结构和旧目录差异很大，必须整体重做。

实际动作：

- 进入高级人工处理弹窗。
- 你手动选择当前原链或候选原链。
- 你手动勾选目录或文件。
- 同步模式使用 `replace_all`
- 执行前必须显式确认风险

这条规则会先清空当前资源目录，再导入所选内容，所以是高风险操作。

#### 规则三：候选人工确认

适合场景：

- 已经发现候选，但你想先看目录结构再决定。

实际动作：

- 进入高级人工处理弹窗。
- 默认更适合使用候选原链。
- 你手动勾选目录或文件。
- 默认同步模式是 `incremental`
- 不会主动删除旧内容

这条规则本质上是“先看，再决定怎么同步”。

### 4.8 追更同步的三种技术模式

追更同步后台真正支持三种 `sync_mode`：

| 模式 | 含义 |
| --- | --- |
| `standard` | 标准安全同步，不允许手动选子目录 |
| `incremental` | 人工选择目录后做增量追加 |
| `replace_all` | 人工选择目录后先清空再全量替换 |

它们和规则的关系是：

- 规则一对应 `current + standard`
- 规则三通常对应 `candidate/current + incremental`
- 规则二对应 `candidate/current + replace_all`

### 4.9 高级人工处理弹窗到底怎么同步

弹窗里当前有两个维度：

- `来源选择`：当前原链 / 候选原链
- `同步模式`：增量追加 / 全量替换

#### 4.9.1 增量追加

行为是：

- 把你勾选的目录或文件继续导入到当前资源目录。
- 不主动删除旧内容。
- 最终仍然基于任务原有分享层级重新创建分享。

#### 4.9.2 全量替换

行为是：

- 先清空当前资源目录。
- 再导入你勾选的目录或文件。
- 最终重新创建分享。

这个模式要求手工确认，因为一旦导入失败，资源目录可能会暂时为空。

### 4.10 追更同步后，分享和发布会怎么联动

追更同步成功后，系统会：

1. 更新任务的当前原链或当前分享。
2. 记录最近一次同步批次。
3. 如果本次用的是候选原链，清空任务里的候选字段。
4. 如果任务已经绑定了运营发布记录，并且允许更新发布记录，则把运营发布里的对外链接同步成最新分享。

也就是说：

- 追更任务和运营发布可以绑定。
- 追更同步成功后，前台运营记录可以自动跟着更新到最新分享。

### 4.11 同集数候选的特殊处理

这是当前追更同步里比较容易忽略，但已经落地的一段逻辑。

当候选满足：

- 是同一作品。
- 不是更高集数。
- 候选集数和当前集数相同。

系统不会把它当成“需要同步的新候选”，而是走同集数处理分支。

#### 4.11.1 同集数候选链接本身健康

如果：

- 同集数候选链接健康。
- 当前分享也健康。

系统会做一次“同平台全局替换”：

- 用当前任务自己的有效分享，替换掉这条同集数候选对应的旧源链接引用。
- 变更类型记为 `same_episode_replaced`

适用含义是：

- 别人的同集数消息也可以被收敛到我们自己的当前有效分享。

#### 4.11.2 同集数候选链接已经失效

如果：

- 同集数候选链接明确失效。
- 当前分享仍然健康。

系统会做更保守的“消息级回写”：

- 只改命中的那一条消息引用。
- 不做全局 `link target` 合并。
- 变更类型记为 `same_episode_rewritten`

这适合把某条已经失效的同集数消息，直接回写成当前任务自己的有效分享。

#### 4.11.3 安全边界

无论是全局替换还是消息级回写，都有同平台校验。

所以不会出现：

- 夸克盘链接把百度盘链接替换掉
- 百度盘链接把夸克盘链接替换掉

### 4.12 追更日志怎么理解

追更详情里的执行终端日志会记录：

- 开始巡检
- 原链校验
- 当前分享校验
- 身份快照构建
- 候选发现 / 丢弃 / 清除
- 创建同步批次
- 同步完成
- 发布联动更新

日志区有两个不同动作：

- `清空当前显示`：只是前端本地隐藏。
- `清理后端日志`：会真正删除数据库中的追更任务日志。

## 5. 运营发布

入口：`资源运营 -> 转存中心 -> 运营发布`

运营发布现在是“资源表”模式，不是单纯的历史日志。

同一资源再次发布到前台时，系统会尽量复用同一条运营记录，而不是无限新增主表行。

### 5.1 运营发布能做什么

当前支持：

- 查看当前运营中的资源。
- 搜索、排序、分页。
- 单条或批量重新发布到前台。
- 批量校验链接。
- 重建分享。
- 退出运营。
- 手动新建发布。
- 查看资源目录预览。

### 5.2 退出运营的三种模式

当前退出运营有三种模式：

| 模式 | 行为 |
| --- | --- |
| `仅归档` | 只从活跃状态移到归档，保留前台消息和网盘资源 |
| `下线前台` | 删除前台消息并解除追更绑定，保留网盘资源目录 |
| `回收资源` | 删除前台消息、解除追更绑定，并尝试删除网盘资源目录 |

实际差异：

- `仅归档` 不释放容量。
- `下线前台` 只清前台，不删网盘目录。
- `回收资源` 才会尝试真正回收网盘资源，适合腾容量。

### 5.3 删除运营记录和退出运营不是一回事

当前项目里：

- `退出运营` 是业务动作，会按模式处理前台消息、绑定和网盘资源。
- `删除记录` 只是删除运营表里的记录，并清理相关绑定，不会替代业务回收动作。

所以正常想“下线资源”时，应优先用 `退出运营`，不是直接删记录。

## 6. 目录预览能力

当前目录预览支持：

- `夸克网盘`
- `百度网盘`

可以用于：

- 批量转存前确认源链接目录结构。
- 追更同步高级处理时手动选目录。
- 运营发布里查看当前资源目录。

当前单次目录预览最多展示前 `200` 项，超出会提示截断。

## 7. 常见使用路径示例

### 7.1 首次转存一个新资源

例子：

1. 在 `选择资源` 里搜到一条夸克源链接。
2. 选择夸克目标账号。
3. 创建批次。
4. 批次成功后，系统生成新的夸克分享，并把系统里的旧引用回写到新分享。
5. 如果这个资源需要长期追更，就从批次项转为追更任务。
6. 如果这个资源需要给前台展示，再发布到运营发布。

### 7.2 已有追更任务，发现更高集数候选

例子：

1. 当前任务最新集数是 22。
2. 最近 3 天内系统又出现了同作品的新消息，标题里明确写到 23 集。
3. AI 判定为同作品且更晚更新。
4. 这条候选先被保存到任务里。
5. 你可以走规则一继续同步当前原链，也可以走规则三先人工看候选目录，再决定增量或全量。
6. 如果最后应用候选并同步成功，任务当前原链会切到候选，新分享也会刷新；若已绑定运营发布，前台链接也会一并更新。

### 7.3 同集数候选但对方链接已经失效

例子：

1. 当前任务自己的分享还有效，当前最新集数是 18。
2. 系统里又找到一条同作品、同样也是 18 集的消息。
3. 但那条消息里的网盘候选已经失效。
4. 这时系统不会把它保存成新候选。
5. 如果命中消息引用可定位，系统会把那条消息里的失效链接回写成当前任务自己的有效分享。

## 8. 使用时要注意的边界

- 转存中心里的“回写链接”都是改系统内数据，不是改 Telegram 远端原消息。
- 追更候选召回和链接替换都严格按同平台处理，不会跨盘。
- `原分享目录` 只有在资源目录下存在唯一顶层内容时才会生效，否则自动回退为 `资源目录`。
- `规则二：全量替换` 风险最高，因为会先清空当前资源目录。
- 清理后端日志会真实删除数据库日志，不是只清前端显示。
- 目录预览目前只支持百度和夸克。

## 9. 一句话总结

可以把转存中心理解成四个分工明确的模块：

- `网盘账号` 负责“谁来转”。
- `批量转存` 负责“先把资源转进来并生成自己的分享”。
- `追更同步` 负责“后续怎么巡检、找候选、同步、更新绑定发布”。
- `运营发布` 负责“哪些资源正在前台运营，以及如何下线或回收容量”。

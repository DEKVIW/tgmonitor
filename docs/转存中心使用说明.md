# 转存中心使用说明

> 版本说明
>
> - 本文面向当前后台 `资源运营 -> 转存中心` 模块。
> - 覆盖当前已经上线的 4 个子页签：`网盘账号`、`批量转存`、`追更同步`、`运营发布`。
> - 本文只写当前真实实现的能力；尚未完成的能力会明确标注为“未实现”或“后续阶段”。

## 1. 模块总览

当前的“转存中心”已经不是单一的“手动转存”入口，而是一个完整的资源处理模块，包含 4 个子页签：

1. `网盘账号`
   用来配置百度网盘、夸克网盘账号，设置默认保存根目录、默认分享方式、提取码和有效期。
2. `批量转存`
   用来从系统里已有消息中筛出可转存的网盘链接，创建批次，进入 `tg-worker` 队列执行转存、创建新分享、校验新分享、回写新链接。
3. `追更同步`
   用来跟踪“已经处理过的资源”，定期检查原链和当前对外分享是否异常，并尝试发现同一资源的新候选来源。
4. `运营发布`
   用来把资源手动发布到前台，既支持从转存成功项一键发布，也支持完全手动新建发布。

建议理解为：

- `批量转存` 负责“一次性处理”
- `追更同步` 负责“持续跟踪”
- `运营发布` 负责“对前台展示”

## 2. 当前已实现与未实现边界

### 2.1 已实现

- 配置并校验百度网盘、夸克网盘账号
- 按“最近消息”或“时间范围”预览待转存候选
- 按原链去重后创建手动批次
- 支持批次草稿、立即启动、失败自动重试、失败后手动立即重试
- 支持两种目录布局：
  - `独立目录`
  - `批次归档`
- 支持两种分享层级：
  - `分享资源目录`
  - `优先分享原分享目录或文件`
- 支持资源目录自定义命名模板
- 支持批次执行终端日志、批次项明细日志、日志清理
- 支持转存成功后创建新分享链接
- 支持对新分享链接进行校验
- 支持将旧链接回写为新链接
- 支持从批次项创建追更任务
- 支持追更任务的暂停、恢复、立即检查、删除
- 支持从批次项一键发布到前台
- 支持手动新建一条运营发布
- 支持独立保存“运营发布记录”，不会因为删除批次而丢失

### 2.2 当前未实现

- `查看原链目录`
- `查看新分享目录`
- 追更任务命中候选后自动执行“递增转存 -> 新分享 -> 校验 -> 回写”
- 基于分享者身份、作者身份等更强特征的自动追更
- 在“运营发布”里直接撤回/删除发布记录

当前最重要的一点是：

- `追更同步` 现在主要是“发现问题、发现候选、记录日志、留出后续自动化入口”
- 它还不是“自动追更并自动换新链接”的完整闭环

## 3. 术语解释

为避免后续继续混淆，先把几个关键术语固定下来。

### 3.1 账号根目录

网盘账号配置里的“默认保存根目录”。

例如：

- `TG`
- `影视/TG`
- `转存库/夸克`

这是系统所有转存内容的起点目录。

### 3.2 批次目录

只有在“目录布局 = 批次归档”时才会出现。

例如批次目录名为 `batch-12`，那么它位于：

```text
账号根目录/batch-12
```

它的作用只是把同一次批量任务归档到同一个上层目录里，方便管理。

### 3.3 资源目录

每一条原链在目标网盘里对应的那个系统级目录。

这是当前三期转存里最核心的目录概念。

例如：

- `tg-transfer-4-9-1999-4k-1157`
- `20260413-乾隆王朝-{item_id}`

资源目录的作用是：

- 为单条原链提供独立落点
- 避免不同资源相互覆盖
- 为后续分享、校验、回写、追更记录固定目标路径

可以把它理解成：

- 账号根目录下面的“资源容器目录”
- 当前默认对外分享的，也是这个目录

### 3.4 原分享目录或文件

原始分享链接真正包含的内容。

例如：

- 一个文件夹：`牧神记(2025) 更78集`
- 一个文件：`乾隆王朝.mkv`
- 多个并列文件/目录

这些内容会被转存到“资源目录”里面。

### 3.5 当前对外分享

系统最终返回给前台或后续流程使用的那个新分享链接。

当前它可能指向两种层级：

1. `资源目录`
2. `原分享目录或文件`

具体由“分享层级”配置决定。

## 4. 网盘账号

入口：`资源运营 -> 转存中心 -> 网盘账号`

当前前端只开放了两个平台：

- 百度网盘
- 夸克网盘

每个账号包含这些关键字段：

- `平台`
- `账号名称`
- `Cookie`
- `默认保存根目录`
- `默认分享方式`
- `默认提取码`
- `默认有效天数`
- `启用`
- `设为默认`

### 4.1 默认分享方式

当前有两种：

- `转存后继续分享`
- `仅转存不公开`

说明：

- 如果选择公开分享，批次执行会在转存成功后继续创建新分享链接
- 如果选择私密分享，并且没有填写提取码，系统会自动生成一个 4 位提取码

### 4.2 账号校验

“校验账号”只做账号连通性检查，不会校验每一条原链。

也就是说：

- 它验证的是“这个 Cookie 当前是否还能正常操作该平台账号”
- 它不是“帮你提前验证所有待转存原链是否有效”

## 5. 批量转存

入口：`资源运营 -> 转存中心 -> 批量转存`

这是当前三期的主入口。

完整流程是：

1. 先生成预览
2. 勾选要处理的原链
3. 创建批次
4. 进入 worker 队列执行
5. 查看执行终端与明细
6. 失败时立即重试或自动重试
7. 成功后可一键发布到前台
8. 成功后可转为追更任务

### 5.1 预览筛选

#### 选择方式

有两种：

- `最近消息`
- `时间范围`

#### 遍历方向

有两种：

- `最新优先`
- `最早优先`

这决定的是本次扫描消息时的顺序，不影响最终转存逻辑。

#### 平台筛选

当前可多选：

- 百度网盘
- 夸克网盘

留空表示不过滤平台。

#### 来源健康筛选

当前有三种：

- `全部`
- `仅正常`
- `排除失效`

这里一定要注意：

- 这里看的不是“本次实时校验”
- 而是系统历史上已经跑过的链接检测结果

所以它的含义是：

- `仅正常`
  只保留历史巡检结果明确为有效的链接
- `排除失效`
  排除历史巡检已确认失效的链接，但保留“未知”
- `全部`
  不按历史巡检结果过滤

实际使用建议：

- 优先用 `排除失效`
- 少用 `仅正常`

因为很多还没被巡检到的链接会是“未知”，如果用“仅正常”，可能把本来可转存的链接全部过滤掉。

### 5.2 预览列表怎么来的

预览列表不是直接按消息逐条展示，而是：

1. 先扫描选中的消息范围
2. 取出其中的网盘链接
3. 按原链去重
4. 汇总这条原链影响了多少消息、多少引用

所以预览里的每一行，代表的是：

- `一条唯一原链`
- 而不是 `一条消息`

这也是为什么列表里会有：

- 影响消息数
- 影响引用数

### 5.3 创建批次前必须知道的事

“创建批次”只会处理当前勾选的原链。

如果没有勾选，创建时会报：

```text
no transferable items selected
```

正确顺序是：

1. 先生成预览
2. 在表格里勾选候选
3. 再点“创建批次”

### 5.4 创建批次配置说明

#### 创建后立即启动

- 打开：批次创建完成后立刻进入 `tg-worker` 队列
- 关闭：只保存为草稿，稍后手动启动

当前默认值：

- `开启`

#### 最大尝试次数

单条批次项最多自动执行多少次。

当前默认值：

- `3`

#### 自动重试间隔

单条批次项失败后，如果还允许重试，多久后再次自动尝试。

当前默认值：

- `10 分钟`

可选项：

- 不自动重试
- 1 分钟
- 5 分钟
- 10 分钟
- 30 分钟
- 60 分钟

说明：

- 设为 `0` 时，不会自动重试
- 即使关闭自动重试，失败项仍然支持手动“立即重试”

#### 目录布局

有两种：

1. `独立目录`
2. `批次归档`

它们只影响资源目录落在哪一层，不影响转存、分享、校验、回写的核心流程。

#### 资源目录名

有两种：

1. `自动生成`
2. `自定义命名`

如果选择自动生成，系统会使用固定格式：

```text
tg-transfer-{batch_id}-{item_id}-{title_slug_auto}
```

例如：

- `tg-transfer-4-9-1999-4k-1157`
- `tg-transfer-3-7-2025-78`

说明：

- 前缀固定为 `tg-transfer`
- 中间包含批次 ID 和批次项 ID
- 末尾是从标题提取出的简化 slug
- slug 只保留英文小写、数字和连字符
- 如果标题里没有可用片段，会回退为 `item-{item_id}`

#### 分享层级

当前有两种：

1. `分享资源目录（默认）`
2. `优先分享原分享目录或文件`

后文会单独详细解释。

### 5.5 路径与目录层级

这是最容易混淆的部分。

#### 情况 A：目录布局 = 独立目录

目录结构：

```text
账号根目录/资源目录/原分享目录或文件
```

例如：

```text
TG/tg-transfer-4-9-1999-4k-1157/三国演义(1994)
```

这时：

- 第一层：账号根目录 `TG`
- 第二层：资源目录 `tg-transfer-4-9-1999-4k-1157`
- 第三层：原始分享内容

#### 情况 B：目录布局 = 批次归档

目录结构：

```text
账号根目录/批次目录/资源目录/原分享目录或文件
```

例如：

```text
TG/batch-12/tg-transfer-4-9-1999-4k-1157/三国演义(1994)
```

这时：

- 第一层：账号根目录 `TG`
- 第二层：批次目录 `batch-12`
- 第三层：资源目录 `tg-transfer-4-9-1999-4k-1157`
- 第四层：原始分享内容

### 5.6 分享层级到底分享哪一层

#### 模式 1：分享资源目录

这是当前默认模式。

会直接分享：

```text
账号根目录/.../资源目录
```

也就是分享系统创建出来的资源目录本身。

优点：

- 最稳定
- 不依赖资源目录下到底有几个顶层内容
- 对后续追更记录也更清晰

适合：

- 大部分常规批量转存任务
- 你希望“每条资源都有独立包装目录”时

#### 模式 2：优先分享原分享目录或文件

这个模式的真实含义不是“强制一定分享原内容”，而是：

1. 先进入资源目录
2. 检查资源目录下的顶层内容数量
3. 如果刚好只有 1 个顶层目录或文件
4. 就直接分享这个唯一的顶层内容
5. 如果不是 1 个，就自动回退为分享资源目录

也就是说，只有在下面这种情况下才会直接分享原内容：

```text
资源目录/
  └── 原分享目录或文件（且只有这一项）
```

如果资源目录下是：

```text
资源目录/
  ├── 文件 A
  ├── 文件 B
  └── 文件 C
```

或者：

```text
资源目录/
  （空）
```

系统都会回退为：

- 分享资源目录

这一点当前已经在百度、夸克 provider 中做了真实回退处理。

#### 这两种模式怎么选

推荐：

- 默认用 `分享资源目录`
- 只有当你明确希望“最终打开分享链接时就直接看到原始唯一目录或唯一文件”时，再用 `优先分享原分享目录或文件`

### 5.7 资源目录命名模板

如果“资源目录名”选择 `自定义命名`，可以使用下面这些模板字段。

| 模板字段 | 含义 | 示例 | 说明 |
| --- | --- | --- | --- |
| `{title}` | 标题的安全版本 | `三国演义 1994 全集` | 会移除非法路径字符，压缩空白，保留中文 |
| `{title_slug}` | 标题的 slug 版本 | `1994`、`1999-4k-1157` | 只保留英文小写、数字、连字符；中文本身不会直接保留 |
| `{platform}` | 平台名 | `百度网盘`、`夸克网盘` | 会做路径安全清洗 |
| `{batch_id}` | 批次 ID | `4` | 对应 `PanTransferBatch.id` |
| `{item_id}` | 批次项 ID | `9` | 对应 `PanTransferBatchItem.id` |
| `{share_key}` | 原链平台侧的分享标识 | `8db5b659e2eb` | 能提取时很适合拿来防重 |
| `{date}` | 渲染日期 | `20260413` | 当前按服务端渲染时间输出 `YYYYMMDD` |

#### 重要规则 1：最终目录段会做安全清洗

会自动处理：

- 去掉非法路径字符
- 压缩连续空格
- 去掉头尾的空格、点、下划线、连字符
- 最长保留 96 个字符

#### 重要规则 2：如果模板里没有唯一标识，系统会自动补后缀

如果你的模板里 **没有** 包含下面任意一个：

- `{item_id}`
- `{share_key}`

系统会自动在末尾补：

```text
__i{item_id}
```

例如模板：

```text
{date}-{title_slug}
```

渲染后可能会变成：

```text
20260413-1999-4k-1157__i9
```

这样做是为了避免同批次里多个资源因为标题接近而撞目录。

#### 重要规则 3：`{share_key}` 不是永远都有值

如果某条源链接无法提取分享标识，`{share_key}` 会退化为占位值，而不是保证一定有真实 key。

所以：

- 如果你非常依赖唯一性，建议同时带上 `{item_id}`
- 不建议只写 `{share_key}` 一项后就完全假设所有平台、所有链接都能稳定拿到值

#### 推荐模板

适合大多数场景：

```text
{date}-{title_slug}-{item_id}
```

平台区分更明显：

```text
{platform}-{date}-{title_slug}-{item_id}
```

更贴近链接身份：

```text
{platform}-{share_key}-{item_id}
```

#### 不推荐模板

不推荐只写：

```text
{title}
```

虽然系统会自动补 `__i{item_id}`，但长期看仍不够规整，也不方便批量浏览。

### 5.8 当前不支持“一个批次共用同一个资源目录”

当前实现中：

- 每一条原链都会创建自己的资源目录
- 不会把同一批次的所有原链都塞进同一个资源目录里

也就是说，目前的资源目录一定是“单资源对应单目录”。

这样做的原因是：

- 避免不同资源互相覆盖
- 方便失败重试、日志定位、回写替换
- 方便后续把单条成功项转成追更任务

### 5.9 批次执行阶段

单条批次项的大致执行顺序是：

1. `转存`
2. `分享`
3. `校验`
4. `回写`
5. `完成`

其中：

- `转存`
  把原链内容转到目标账号的资源目录
- `分享`
  按配置创建新分享链接
- `校验`
  对新分享链接做有效性校验
- `回写`
  用新链接替换系统里旧链接的引用
- `完成`
  标记这一项成功或失败

### 5.10 执行日志怎么看

批次详情侧边栏里有两种视角：

#### 批次执行终端

按真实执行顺序汇总所有批次项的关键日志。

适合排查：

- 当前卡在哪一步
- 哪一项失败了
- 是否已经创建分享成功
- 回写是否完成

当前运行中的批次，详情侧边栏会自动轮询刷新，不需要整页手动刷新才能看到新日志。

#### 批次项展开日志

只看某一条资源的明细执行过程。

适合排查单条资源。

### 5.11 失败与重试

当前支持两种重试方式：

1. 自动重试
2. 手动立即重试

#### 自动重试

是否自动重试、间隔多久，取决于创建批次时的配置。

#### 手动立即重试

批次详情里：

- 可以重试整批失败项
- 也可以只重试选中的失败项
- 也可以只对单条失败项点“立即重试”

#### 当前重试行为的重要说明

如果某条资源已经成功转存到暂存目录，但后面是在“分享”或“回写”阶段失败：

- 系统会优先复用已有暂存目录快照
- 不会无脑重复再转存一次

因此你在日志里可能会看到类似：

```text
Skipping transfer and reusing existing staging snapshot
```

这表示：

- 目录已经准备好了
- 本次重试直接从分享或后续步骤接着走

### 5.12 删除批次会删什么，不会删什么

删除批次 **只删除系统里的批次数据和日志记录**，不会做网盘侧清理。

会删掉：

- 批次记录
- 批次项记录
- 执行日志
- 回写日志

不会删掉：

- 原始消息
- 已经转存到网盘里的目录
- 已经创建的新分享链接
- 已发布到前台的消息
- 运营发布记录

所以删除批次的正确理解是：

- “清理系统里的这次任务记录”
- 不是“回收网盘里的真实资源”

### 5.13 日志里的 `#7`、`#8` 是什么

批次终端日志里的 `#7`、`#8` 指的是：

- 批次项 ID，也就是 `PanTransferBatchItem.id`

它是全局自增的，不会因为你删除旧批次而回退或重排。

所以：

- 删除了前面的批次
- 新建批次后出现更大的编号

这是正常现象。

## 6. 追更同步

入口：`资源运营 -> 转存中心 -> 追更同步`

### 6.1 当前追更任务怎么来

当前不是自动全局生成追更任务，而是：

- 先在 `批量转存 -> 批次详情` 里选中一条资源
- 再点 `转为追更任务`

也就是说，当前追更是“人工确认后纳入跟踪”。

### 6.2 创建追更任务时会记录什么

系统会把下面这些信息带进去：

- 原始链接
- 当前对外分享链接
- 目标账号
- 固定目标目录
- 当前的目录布局
- 当前的资源目录模板信息
- 当前的分享层级
- 关联作品信息（如果已有作品归并结果）
- 来源消息快照

这也是为什么当前三期先把“路径、分享层级、回写结果”做对很重要。

### 6.3 追更任务当前会做什么

当前每次巡检会做 3 件事：

1. 校验原链是否正常
2. 校验当前对外分享是否正常
3. 尝试寻找“同一资源”的新候选原链

### 6.4 “同一资源”现在怎么判断

当前不是靠“分享者 ID”或“作者 ID”来判断。

当前优先级是：

1. 如果这条资源已经成功归并到 `作品(work)`，优先按同一 `work_id` 找最近 30 天的新候选链接
2. 如果没有作品归并结果，就退化为按 `topic_title` 在最近 30 天消息标题、描述、展示文本里做模糊匹配

所以当前追更更准确地说是：

- `作品级/主题级候选发现`
- 不是 `平台作者级精准追更`

### 6.5 当前追更不会自动做的事

当前发现候选后，不会自动：

- 把候选链接重新转存到固定目录
- 自动创建新分享
- 自动校验并回写

当前只会：

- 记录候选
- 更新任务状态
- 写日志，提醒管理员后续处理

这块是后续四期、后续自动化阶段要继续完成的内容。

### 6.6 追更状态说明

当前常见状态有：

- `正常跟踪`
- `等待检查`
- `检查中`
- `发现候选更新`
- `原链失效`
- `新分享异常`
- `检查失败`

### 6.7 检查频率

当前后端默认检查间隔是：

- `6 小时`

后端限制范围：

- 最短 `15 分钟`
- 最长 `7 天`

当前前端创建追更任务时没有开放这个配置项，所以创建后默认按 6 小时运行。

### 6.8 任务控制

当前支持：

- `立即检查`
- `暂停`
- `恢复`
- `删除`

说明：

- `暂停` 后不会继续自动巡检
- `恢复` 后会重新进入待检查队列
- `立即检查` 会把任务直接加入当前队列

### 6.9 追更日志

追更详情里也有终端式日志，主要用于查看：

- 原链校验结果
- 当前对外分享校验结果
- 是否发现新候选
- 本次检查何时结束

### 6.10 删除追更任务会删什么

会删掉：

- 追更任务记录
- 追更任务日志

不会删掉：

- 已经转存的目录
- 当前对外分享
- 原始消息
- 已发布到前台的消息

## 7. 运营发布

入口：`资源运营 -> 转存中心 -> 运营发布`

当前有两种来源：

1. 从批次项一键发布
2. 手动新建发布

### 7.1 从批次项一键发布

入口：

- `批量转存 -> 批次详情 -> 发布到前台`

当前发布时的链接选择优先级是：

1. 已经回写成功后的新链接目标 URL
2. 新分享链接
3. 原始链接

也就是说，系统会优先复用已经转存并回写好的新链接。

#### 标题、描述、标签如何预填

当前打开发布弹窗时，会自动预填：

- 标题：批次项标题
- 描述：创建批次时记录下来的来源消息描述快照
- 标签：创建批次时记录下来的来源消息标签快照

注意这里是“批次创建时的快照”，不是实时重新去源消息读取。

### 7.2 手动新建发布

入口：

- `运营发布 -> 手动新建发布`

需要手动填写：

- 平台
- 分享链接
- 标题
- 描述
- 标签

适合场景：

- 并不是从当前转存批次里来的资源
- 已经有现成的新分享链接，只想推到前台

### 7.3 发布后到底发生了什么

发布到前台不是只记一条“运营动作”，而是会真正创建一条新的 `messages` 记录。

所以发布后的效果是：

- 前台会把它当作一条新消息展示
- 它有自己的消息 ID
- 它不依赖原始批次是否仍然存在

同时系统还会额外写一条 `运营发布记录`，专门用来追溯：

- 这条前台消息是从哪里发布来的
- 用的是哪条链接
- 是谁发布的

### 7.4 删除批次后，前台发布会不会消失

不会。

原因是：

- 发布本身已经写成了一条独立的消息记录
- 发布历史也保存在独立的 `pan_transfer_publish_records` 表里

所以：

- 删除批次，不会把已发布到前台的内容一起删除

### 7.5 当前运营发布的限制

当前 `运营发布` 页签主要支持：

- 查看发布历史
- 手动新建发布

当前还不支持：

- 在这个页签里直接撤回已发布内容
- 在这个页签里直接删除发布记录

如果后续要做“运营撤回”，建议作为独立能力补上。

## 8. 推荐使用方式

### 8.1 一次性手动批量转存

适合：

- 临时处理最近一批资源
- 先转过来再说，不一定需要持续追更

推荐流程：

1. 先在 `网盘账号` 配好默认根目录与分享方式
2. 去 `批量转存` 生成预览
3. 用 `排除失效` 作为默认健康筛选
4. 勾选候选
5. 创建批次
6. 默认使用 `分享资源目录`
7. 跑完后根据需要决定是否发布到前台

### 8.2 希望前台展示尽量接近原分享打开效果

适合：

- 原分享本身只有一个顶层目录或一个顶层文件
- 你希望最终打开新链接时直接看到它，而不是先看到包装资源目录

推荐配置：

- 分享层级选择 `优先分享原分享目录或文件`

同时要接受一个事实：

- 如果顶层不是唯一项，系统会自动回退为分享资源目录

### 8.3 先手动转存，再纳入追更

适合：

- 连载剧集
- 持续更新的动漫、综艺、课程
- 你打算后续继续跟踪

推荐流程：

1. 先在 `批量转存` 里完成首轮转存
2. 确认新分享已经创建成功、校验通过、回写成功
3. 对这条批次项点 `转为追更任务`
4. 到 `追更同步` 中观察后续候选变化和异常

### 8.4 从成功转存项直接发布到前台

适合：

- 转存成功后立即对外展示
- 希望尽量复用回写后的新链接

推荐流程：

1. 批次项执行成功
2. 点 `发布到前台`
3. 检查自动带出的标题、描述、标签
4. 如有需要手动润色后确认发布

## 9. 常见问题与重要澄清

### 9.1 `tg-transfer-4-9-1999-4k-1157` 这种目录是什么

这是当前系统里说的“资源目录”。

它不是原分享内容本身，而是：

- 系统为这条原链创建的独立容器目录

原分享内容通常放在它下面一层。

### 9.2 当前默认分享的是哪一层

默认分享的是：

- `资源目录`

不是原分享内容本身。

只有你把分享层级切到：

- `优先分享原分享目录或文件`

并且资源目录下恰好只有一个顶层内容时，才会直接分享原内容。

### 9.3 根目录只有一层时，资源目录是第几层

如果没有开启“批次归档”，就是第二层：

```text
根目录/资源目录/原内容
```

如果开启了“批次归档”，资源目录会变成第三层：

```text
根目录/批次目录/资源目录/原内容
```

### 9.4 当前是否支持“整批共用一个资源目录”

不支持。

当前一定是：

- 一条原链对应一个资源目录

### 9.5 同一个目录再次创建分享，链接会不会还是原来那个

不要依赖这个假设。

从当前实现上看，每次真正执行“创建分享”时，系统都会向网盘平台发起一次新的分享动作，并记录平台返回的新链接。

所以更安全的理解应该是：

- 同一路径不等于同一个分享链接
- 分享链接是否变化，以平台本次实际返回结果为准

### 9.6 如果原作者不用旧链接了，重新发了一个新链接怎么办

这是当前 `追更同步` 想解决的问题之一，但目前只做到“发现候选”，还没做到“自动接力转存”。

当前能做的是：

- 发现原链失效
- 发现同资源的新候选原链
- 记录下来供管理员处理

当前还不能自动做的是：

- 自动把新候选重新转进固定目录并替换现网

### 9.7 批次详情里的日志是实时的吗

对正在运行的批次来说，详情侧边栏会自动轮询刷新，所以打开批次详情后，一般不需要整页刷新就能看到新日志逐步出现。

### 9.8 追更详情里的日志是实时的吗

对于状态为 `等待检查`、`检查中` 的追更任务，详情侧边栏也会自动轮询刷新。

### 9.9 当前支持哪些网盘平台

当前“转存中心”前端只开放：

- 百度网盘
- 夸克网盘

后续要支持更多平台，需要补对应 provider、账号校验、转存、分享与校验链路。

### 9.10 `查看原链目录`、`查看新分享目录` 做了吗

当前还没有。

这两个按钮对应的实际目录浏览能力仍属于后续迭代项。

## 10. 后续阶段建议

如果继续往下做，建议优先级如下：

1. 补 `查看原链目录 / 查看新分享目录`
2. 让追更任务在发现候选后，支持人工确认后一键“接力转存”
3. 再进一步做自动化的“候选命中 -> 固定目录递增转存 -> 新分享 -> 校验 -> 回写”
4. 补运营发布的撤回/删除/重新发布能力
5. 引入更强的资源级追更特征，例如分享者线索、目录内容指纹、同作品多源归并策略

---

如果后续还要继续扩展，这份文档建议优先增补这 4 块内容：

- 目录浏览与文件预览
- 自动追更闭环
- 运营发布撤回与重新推送
- 更多平台的差异化说明
